MCU-Insight

完整指南 三轮诊断案例 报告示例

这东西是干什么的

一共就四件事，没别的。

  • 把一个小组件拷进你的 ESP-IDF 工程，让固件每隔几秒报一次自己的状态
  • 跑一条命令，得到一份给人看的 HTML 报告：固件占多少 Flash 和 RAM、每个任务还剩多少栈、堆最少剩多少、推理慢不慢
  • 出问题的时候，得到一份证据包：所有已知事实，一条条编号，直接粘给任何 AI
  • 再把 AI 的诊断拿回来核对：它会指出 AI 引用了根本不存在的证据

不用联网、不用注册、不用仪器。

动手前，先记住两个路径

下面每条命令都以 cd 开头，所以不管你当前在哪个目录都能直接粘贴。把这两个占位符换成你自己的路径：

  • 工具仓库 = 你克隆 mcu-insight 的那个目录，里面有 docs\ 和 mcu_insight\
  • 你的工程 = 你的 ESP-IDF 工程目录，里面有 CMakeLists.txt（就是 idf.py 能跑的那一层）

最容易搞错的一条：idf.py 在你的工程里跑；mcu_insight 和 sync_firmware.py 在工具仓库里跑。

先拿一个已经坏了的工程练手

examples/leaky-sensor-node/ 是一个故意写坏的小固件，README 里有完整命令，也有答案。先拿它把这份指南走一遍，再动你自己的工程——工具应该报出两条违规，其中一条连作者都没打算埋。

怎么用：三步

1
工具仓库

改脚本顶部四行

打开 tools\insight.ps1，文件最上面有四个变量，每个都有中文注释：

$ProjectDir = "D:\你的工程"          # 你的 ESP-IDF 工程目录
$Partition  = "1500K"                # app 分区大小，留空就跳过
$ComPort    = "COM19"                # 串口号，只有 -Runtime 才用
$Config     = "budgets\light.json"   # 阈值配置，只有 -Runtime 才用

只做静态分析的话，改第一行就够了。

2
工具仓库 · ESP-IDF PowerShell

跑一条命令

cd <工具仓库>
.\tools\insight.ps1             :: 只算 Flash / RAM，不用板子
.\tools\insight.ps1 -Runtime    :: 连板子：采集 + 判定 + 出 HTML 并自动打开

提示"禁止运行脚本"时改用：powershell -ExecutionPolicy Bypass -File .\tools\insight.ps1

3
看结果

三个地方

  • 终端：Flash / RAM 总量、分区余量、Top 占用组件
  • 文件：你的工程\build\insight\analyze.txt
  • HTML：你的工程\build\insight\report.html（只有 -Runtime 才生成）

脚本背后做了什么

1跑 idf.py build，拿到最新的 .map 和 .bin
2跑 mcu_insight analyze，算 Flash / RAM 和分区余量
3加了 -Runtime 才继续：串口采 30 帧 → check 判阈值 → report 出 HTML

只想问"还装得下吗"

不用板子，也不用改脚本，一条命令：

cd <工具仓库>
.\.venv\Scripts\python.exe -m mcu_insight analyze <你的工程>\build\app.map --bin <你的工程>\build\app.bin --partition 1500K

出问题怎么办

找不到 idf.py先打开「ESP-IDF PowerShell」窗口，再跑脚本
禁止运行脚本powershell -ExecutionPolicy Bypass -File .\tools\insight.ps1
串口打不开关掉 idf.py monitor，串口一次只能被一个程序占用
没有 HTMLHTML 只有加 -Runtime 才生成
未映射(不计入) 很大芯片不是 ESP32 原版，地址表要改
analysis 报找不到 .map先 idf.py build 成功一次，产物在 build\ 下

想手动控制每一步

脚本做的事就这些，想拆开自己做时可以对着改。

展开看细节

把组件拷进工程

cd <工具仓库>
python tools\sync_firmware.py <你的工程>

在 main.c 里加三行

#include "mcu_telemetry.h"

mcu_telemetry_config_t telemetry = {
    .device = "my-board", .firmware = "v1.0.0", .report_period_ms = 5000,
};
ESP_ERROR_CHECK(mcu_telemetry_start(&telemetry));

mcu_telemetry_register_task("sensor", TASK_STACK_SENSOR);
mcu_telemetry_set_custom_int("loop_period_ms", 200);

在 main\CMakeLists.txt 里加一个名字

idf_component_register(SRCS "main.c"
                       INCLUDE_DIRS "."
                       REQUIRES mcu_telemetry)

红线配置

复制 budgets/light.json 改成自己的数值，再用 -Config 指过去。

最后你手上有什么

  • 一份 analyze.txt：固件占多少，还差多少到分区上限
  • 一份 report.html：图表 + 阈值判定，双击就能看，不用服务器
  • 一个退出码：0 通过，非 0 失败，可以直接卡 CI

全部在你自己电脑上，没有云端副本。

MCU-Insight

Full guide Case study Example report

What this is

It does four things. That is the whole tool.

  • copy one small component into your ESP-IDF project, so the firmware reports its own state every few seconds
  • run one command and get an HTML report a human can read: how much flash and RAM the build takes, how much stack each task has left, the smallest free heap, how slow inference gets
  • when something is wrong, get an evidence pack: every known fact, numbered, ready to paste into any AI
  • check the AI's answer back against that pack, which catches a citation that does not exist

No network, no account, no instruments.

Two paths to write down first

Every command below starts with cd, so it works from wherever your shell happens to be. Replace the two placeholders with your own paths:

  • tool-repo = the directory you cloned mcu-insight into; it contains docs\ and mcu_insight\
  • your-project = your ESP-IDF project directory, the one with CMakeLists.txt in it (the directory idf.py runs in)

The one thing people get wrong: idf.py runs in your-project; mcu_insight and sync_firmware.py run in tool-repo.

Practise on a project that is already broken

examples/leaky-sensor-node/ is a small firmware with two deliberate defects in it, a README with the commands, and the answers. Walk this guide through that before touching your own project: the tool should report two violations, one of which nobody planted.

Three steps

1
tool repo

Edit four lines at the top of the script

Open tools\insight.ps1. The first block holds four variables, each with a comment:

$ProjectDir = "D:\your-project"       # your ESP-IDF project
$Partition  = "1500K"                 # app partition size, blank to skip
$ComPort    = "COM19"                 # serial port, only for -Runtime
$Config     = "budgets\light.json"    # thresholds, only for -Runtime

For static analysis only, the first line is all you change.

2
tool repo · ESP-IDF PowerShell

Run one command

cd <tool-repo>
.\tools\insight.ps1             :: flash / RAM only, no board
.\tools\insight.ps1 -Runtime    :: board: capture + judge + HTML, opens itself

If scripts are blocked: powershell -ExecutionPolicy Bypass -File .\tools\insight.ps1

3
read the result

Three places

  • Terminal: flash / RAM totals, partition headroom, top consumers
  • File: your-project\build\insight\analyze.txt
  • HTML: your-project\build\insight\report.html (only with -Runtime)

What the script does

1Runs idf.py build and picks up the fresh .map / .bin
2Runs mcu_insight analyze for flash / RAM and partition headroom
3With -Runtime: 30 frames over serial → check → report

Just asking "does it still fit?"

No board, no script edit, one command:

cd <tool-repo>
.\.venv\Scripts\python.exe -m mcu_insight analyze <project>\build\app.map --bin <project>\build\app.bin --partition 1500K

When something fails

idf.py not foundOpen the ESP-IDF PowerShell window, then run the script
Scripts blockedpowershell -ExecutionPolicy Bypass -File .\tools\insight.ps1
Serial port busyClose idf.py monitor; one program per port
No HTMLHTML is only produced with -Runtime
Unmapped (not counted) is largeNot a stock ESP32 — the address map needs updating
analyze cannot find the .mapRun idf.py build successfully first

Prefer to drive every step yourself

This is all the script does, if you want to take it apart.

Show the details

Copy the component in

cd <tool-repo>
python tools\sync_firmware.py <your-project>

Three lines in main.c

#include "mcu_telemetry.h"

mcu_telemetry_config_t telemetry = {
    .device = "my-board", .firmware = "v1.0.0", .report_period_ms = 5000,
};
ESP_ERROR_CHECK(mcu_telemetry_start(&telemetry));

mcu_telemetry_register_task("sensor", TASK_STACK_SENSOR);
mcu_telemetry_set_custom_int("loop_period_ms", 200);

One name in main\CMakeLists.txt

idf_component_register(SRCS "main.c"
                       INCLUDE_DIRS "."
                       REQUIRES mcu_telemetry)

Thresholds

Copy budgets/light.json, change the numbers, point -Config at it.

What you end up with

  • analyze.txt: what the image costs and how much partition is left
  • report.html: charts plus verdicts, double-click, no server
  • An exit code: 0 pass, non-zero fail — gate CI on it

All local. Nothing is uploaded.
